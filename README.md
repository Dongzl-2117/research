# 投资研究库

给 **investment.zldong.com** 用的私人研究库。仓库名仍然是 `research`。

这里保存几位作者的全文归档。首页按天推送，也可以按作者、按公司分模块查看，并做中文全文检索。它不是新闻流水线。

## 运行

```bash
cp .env.example .env
docker compose up -d --build
```

浏览器只通过本机 `http://127.0.0.1:8088` 访问。公网入口是 Cloudflare Tunnel 转到这个地址，前面再加 Cloudflare Access。应用自己不提供登录。部署步骤见 [docs/deploy.md](docs/deploy.md)。

## 页面

- 按天：首页。只排 `timeline: true` 的来源（公众号、知识星球；飞书文库不进这一列）。文章按上海日历从新到旧，同一天里也是新的在前。翻页按整天翻，可以跳到某一天（`/?date=YYYY-MM-DD`）。点日期进入日汇总。卡片优先显示摘要；还没有摘要时用正文里的一句实质内容，不拿点赞、sn、时间戳当导读
- 按天的首页顶部有「持仓近况」：持仓和观察的公司各自最近一篇深入谈到它的文章（整理过观点的直接显示作者的判断和态度），和近 30 天的篇数。备份、定时任务、Grok 出了问题，或者定时导入的来源停更明显超过平时的间隔时，顶上提示一行；正常时什么都不显示
- 作者：每位作者的篇数、时间跨度、最近一篇、常深入谈的公司；作者页可以只在他的文章里检索
- 公司：持仓和观察的放在最前，每家一张卡，带深入篇数、近两年每月深入篇数、主要作者和最近一篇；其余公司按深入篇数排，可按市场筛、按最近提及排。公司页有四格统计、按月的深入 / 一带而过柱状图、「谁在谈」作者分布，文章按年份分组，默认只看深入提及，每篇显示提及原句。持仓和观察公司另有「论点」和「观点」：论点把作者们的判断按机制归成几条，支持和反对各几篇、谁站哪边；观点时间线每篇一条作者判断和机制，原文谈到时带风险、推翻条件、验证指标，可以只看风险与反方、只看态度变化、只看某条论点
- 检索：输入关键词或直接问一句话。所有词都命中的文章排前面、按相关度排序，每篇给最相关的原文段落；其后是只命中一部分的。图片里的字（OCR）也能搜到。可按作者、公司、日期过滤，检索词是公司或作者名时直达。怎么找、准不准、库大了快不快见 [docs/retrieval.md](docs/retrieval.md)
- 问库：先在库里召回最相关的原文段落，马上列出来；Grok 在后台补同义说法、再检索一遍，只依据原文整合，先写判断、再写作者给出的机制，数字只作证据，每句带出处。资料多时分批读完再汇总。写完逐句核对出处，数字、引号、作者、日期对不上的列出来。每段原文可以标「不相关」，也可以补「漏了」的文章，这些标注用来回放评测
- 文章：标题、时间和正文。从问库、观点的出处点进来，直接滚到被引用的那几段并标出来。底部「同期别人怎么看」列出别的作者前后 30 天对同一家持仓公司的判断。作者改过或删过的稿，署名行标出来，点进去看各版改了什么。英文稿可站内 Grok 译成中英对照（见 [docs/translate.md](docs/translate.md)）。图片从本机磁盘读，外链图片也下载到本地。Markdown / JSON 仍在 `/api/v1`
- 重复文章：认出来的同一篇，每组留下哪份、藏起哪几份、重合多少，认错了点一下拆开

给 AI 用的 JSON 接口、MCP 和 `/llms.txt`，以及与 AIHOT 共用的 Grok 登录，见 [docs/llm.md](docs/llm.md)。

## 来源

白名单在 `config/sources.yaml`。现在启用方伟公众号、方伟知识星球、乘风破浪、林文丰飞书、孤独进化体。林文丰公众号停用，不入库。

持仓和观察名单在 `config/portfolio.yaml`，按公司表里的中文名写。首页「持仓近况」、公司列表置顶、公司页的「持仓 / 观察」标记都读它，改完刷新页面即可。

导入命令、幂等规则、改稿删稿怎么处理、去重、外链图片和计数报告见 [docs/ingest.md](docs/ingest.md)。公司提及的判定和歧义别名的规则见 [docs/mentions.md](docs/mentions.md)。备份、试恢复、夜间补齐、定时增量导入和出问题时的提示见 [docs/backup.md](docs/backup.md)。图片里的字见 [docs/ocr.md](docs/ocr.md)。

## 数据

Postgres 使用 zhparser 做中文全文检索。正文在库里，图片在 `data/images`。不要把 `.env`、归档压缩包或 `data/` 提交进仓库。

正文另外切成段落块存在 `article_chunks`，检索片段和问答引用落在块上；英文文章的中文译文也切块进检索。同一篇从两条路导入的，只留一个主版本。语义检索留了接口，但没有安装 pgvector，也没有向量列，原因见 [docs/retrieval.md](docs/retrieval.md)。

## 开发

```bash
pip install --require-hashes -r requirements-dev.lock
pip install --no-deps -e .
ruff check .
pytest
```

依赖的版本和 hash 锁在 `requirements*.lock` 里，改依赖、升级依赖用 `scripts/lock.sh`，见 [docs/deploy.md](docs/deploy.md)。

集成测试需要带 zhparser 的 Postgres，并使用名为 `research_test` 的库。`docker compose up -d db` 之后创建这个库即可。CI 会自己构建数据库镜像并跑这些测试，再用 1500 篇的评测语料跑一遍检索评测，准确率、召回率比基线退步就失败；另外构建应用和 OCR 镜像，认一张样图。
