## 显式定向修复流程（仅计划，本轮未执行）

1. 先固定文章 ID、来源、external_id、当前哈希和 raw 路径清单，在隔离数据库预演。
   `group.owner.user_id`、话题作者账户和完整评论作者分别核对；回复收件人不能当作者。
   只对有充分证明的记录生成 owner/reply 投影；未知保持可回溯未知，保留原始正文与 raw。
2. 重导入仅包含批准话题的最小归档：匹配 Markdown、群元数据、话题 JSON、完整评论 JSON 及必要附件。
   `research-ingest-zsxq --source fangwei-zsxq --input <限定归档目录>` 是写入入口，且会维护派生表和导入状态；
   没有文章级 dry-run，必须先隔离预演。逐项确认 existing external_id 与文章 ID 不变，兼顾旧日期前缀格式，
   禁止误建并行副本。现有 `research-repair-zsxq --spot` 只限定抽验，**不限定修复范围**，不能拿它替代定向计划。
3. 重建账户验证的正文／回复块及公司提及，失效旧投影缓存。仅原文精确包含的已证实块可沿用；
   旧摘要、观点、译文、历史回答及向量不得仅通过改版本字段或对齐哈希恢复可信。
4. OCR 逐篇复核原图和关联。先完成正文投影，再用明确处理入口从真实 `image_texts` 重组；
   需要颜色证据时定向读原图，禁止从位置或既有“方伟：”推断。原图缺失则继续未知。
   不直接补 `ocr_role_version=4`，不为召回放宽身份。若需重新 OCR、embedding 或生成，另列处理量及预算获批。
5. 对同一文章／段落清单核对修复前后 ID、来源、可见性、引用锚点、缓存版本及资格数量。
   应保留的真实作者／回复必须恢复，7 篇缺证 guest 不能误入；再评测跨主题正负例及留出集。

最小后续读取范围应先固定为：23725 的一个话题及完整评论文件；
23589、12176、23829、23663 四篇对应上表的 **7 个 OCR 锚点**。
只读这些锚点的图片关联（文章、来源、哈希、原引用、存储路径）、已有原始 OCR、当前证明字段及哈希；
每条查询 5 秒 statement timeout、1 秒 lock timeout，最多 7 行关联／7 条 OCR（每条最多 5000 字）。
只查看对应原图，不新增全文导出、不抓取、不生成 OCR。本轮未执行这些额外读取；先核实授权边界及精确文件清单。

## 纯招募段过滤边界

新增过滤只作用于 `retrieval.score_rows`，因而影响搜索／问库排序候选，不改 raw、正文、段落表或向量索引。
只认明确扫码／点击入群指令及完整的招募、讨论安排和联系说明；不能只凭“欢迎加入”判定。
混合研究段、数字事实、引用／代码块、会员商业机制与扫码支付讨论保留；独立引用章节中的推广文案也保留。
无法确定为纯招募时保留。过滤不代替人工语义审阅，也不修正作者原文中的事实判断。
