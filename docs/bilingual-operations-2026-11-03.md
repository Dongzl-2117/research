# 双语定向干跑、停用来源与历史回执冲突（2026-11-03）

基于 main `5c19a8e183983181497617c4b9f17c1b33d162eb`，已包含 #217、#218。这里只修复三项运维边界；#218 的纯数字表格校验保留原样。所有数据库与模型替身都使用合成资料，没有执行正式查询、历史改写、真实模型请求或上线操作。

## 指定文章的干跑范围

`research-translate --recheck --dry-run --article-id 990001` 现在只读该编号，不再扫描整条重检队列。重复的编号按首次出现去重，保留请求顺序。与实际指定文章的处理一致，显式编号优先于 `--source`、`--limit`；这两个选项只约束未指定编号的队列扫描。

干跑使用 `connect` 和只读事务，不调用 `prepare`、认证或模型。每个指定编号分别报告 `explicit-article`、`source-disabled` 或 `not-found`；“可处理”只说明存在且来源启用，实际翻译仍须通过语言、正文和结果校验。虚构编号 990001 仅用于说明，本文没有要求执行任何正式命令。

## 停用来源

待译和重检都在 SQL 的 LIMIT／扫描上限之前过滤 `sources.enabled`，显式 `--source` 也不能绕过。显式 `--article-id` 来自停用来源时直接 skipped，不请求模型、不写译文或中文块。来源在模型请求期间被停用，则写回前加锁并复核来源状态，拒绝本次结果；已有好译文与中文检索块原样保留。

## 旧回执与当前中文发生冲突

能够从旧回执重建旧目标，只证明旧快照完整，并不证明覆盖当前中文无损。当前目标与候选在规范化后有任何差异（包括增删段、措辞、链接、代码空格和出现顺序），分类改为 `target-conflict`，建议 `review-target-edits`。缺段也保守列为冲突，因为无法推断删除是否有意。

计划仍只含分类、hash、数量和建议，不含正文；始终 `writes=false`、`modelCalls=0`。当前稿未变仍为 mapped。源或版本不兼容仍按原规则列为 unmapped，不能补签回执。历史恢复须另外逐篇比较并明确授权；本改动没有 apply 入口、迁移或批量任务。
