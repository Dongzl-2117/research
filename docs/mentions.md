# 公司提及深度

一家公司在一篇文章里只有一个深度。判断顺序如下。

1. **标题**：标题里出现这家公司的任一别名。
2. 正文没有 Markdown 标题时，整篇当成一块：
   - 出现不少于 3 次：**全文**
   - 否则：**一带而过**
3. 正文有 Markdown 标题时：
   - 至少两个章节命中，或同一个章节里出现不少于 6 次：**全文**
   - 只命中一个章节，且不少于 2 次：**单节**
   - 其余，通常是某一章里的一次：**一带而过**

次数按不重叠的命中算。标题里的命中和正文里的命中加在一起，记在文章页和公司页的「次数」上。深度被标题截获以后，正文里再出现也不会把深度降级。

## 别名怎么匹配

匹配不走分词器，避免「茅台」被收进「贵州茅台」这种词之后对不上。

- 中文按字面、从左到右、同一位置保留更长的别名。「贵州茅台」算一次，不会再拆出一次「茅台」。
- 英文和股票代码按词边界。带数字或点号的代码不区分大小写。
- 纯字母且长度不超过 2，以及 `Meta`、`META`、`Apple`、`COST`、`BOE`、`ARM` 这些容易撞进普通单词的写法区分大小写。
- 同一个别名只能属于一家公司。种子数据如果冲突，进程启动时会直接报错。

短名字仍可能误伤。种子里故意没放单独的「平安」「理想」「药明」。保留了「苹果」「字节」「贝壳」「小米」这类你点名要的简称，公司页上的「一带而过」就是用来装这些顺带提到的情况。

两地上市合成一条记录，代码列放主上市地，另一个代码放在简称里。例如比亚迪的代码是 `002594.SZ`，简称里有 `01211.HK`。

改别名之后运行 `research-rebuild-mentions`。只重新导入而未改动正文的文章，不会自动重算提及。

## 和全文检索的区别

全文检索用 Postgres 的 zhparser（`chinese` 配置），并打开：

- `zhparser.punctuation_ignore`
- `zhparser.seg_with_duality`
- `zhparser.multi_short`

后两个是为了把词典里没有的二字词（例如「美团」「财报」）补进索引。片段高亮在应用里按你输入的原文做，不用 `ts_headline`，免得二字复合把摘要打乱。

检索索引是 `articles.search_tsv` 上的 GIN。正文存在生成列里，导入时顺手写好，不需要另跑一遍全表扫描才能搜索。公司提及是另一张 `article_mentions` 表，用内存里的自动机扫每篇文章，公司数量是几百这个量级，文章到几万篇时仍然是逐篇线性扫描。
