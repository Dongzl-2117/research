## 真正共用的流程

侧栏不再发送 `chat=true`，也不传旧对话。`/api/v1/ask` 的普通入口直接调用原来的
`ask.start`，由同一个 `ask.run_job`／执行器扩词、`purpose=deep` 检索、分批摘录、汇总、引用编号和写回。
同步 API 的 `ask` 也调用同一条链。删除了独立的 `article_chat` 模型提示、人工补库、执行器及答案写入代码。
没有改写 `ask.py`、`retrieval.py`、原文／OCR 整理、模型配置或历史行。

侧栏仍轮询 `/api/v1/answers/{id}`，保留原问库的 `checks`、`terms`、`stats` 和 `failed_batches`。
核对提示和未读批次会显示，全部检索段落可展开，引用可回原文；每条已登记回答都有完整回答页链接。
没有模型凭证时仍展示原始召回段落，和原问库一样不创建模型任务。

## 范围和历史的明确变化

旧侧栏是“当前文章优先，再补少量其他文章”，不是原问库的一般检索。本轮不声称两者完全相同：

| 选择／行为 | 新侧栏 |
| --- | --- |
| 默认“整个资料库” | 和问库不传 `article` 时一样，检索当前启用资料；不自动优先当前文章 |
| 显式“只问这篇” | 传当前 `article`，严格使用原问库的文章范围；不自动补其他文章 |
| 作者／来源等 API 范围 | 仍由原 `resolve_scope` 解析，不由侧栏另行扩大或绕过 |
| 多轮 | 前几轮只是界面记录，每次仅提交当前问题；不做指代消解、不把旧回答当新证据 |
| 单轮提示 | 范围选项标明“单轮”，输入框和范围控件关联屏幕阅读器说明；每个问题保留当时所选范围 |
| 问库历史 | 新问题按普通问库规则进入“最近问过”；旧 `scope.chat` 行保持原有隐藏规则，不重写 |
| 清空／离开页面 | 清掉浏览器显示记录，不删除问库记录，也不承诺取消已经登记的后台任务 |

原 `chat=true` 的 `article` 是优先上下文，不能静默把它解释成仅检索一篇。
所以旧请求明确返回 400，提示刷新后选择范围；`/llms.txt` 同步更新。不支持靠旧 `history` 接着追问。
历史回答和其回执不删除；旧任务重试也使用原问库流程，旧 `history` 不参与生成。

## 重试和网络恢复

- `status=error` 的“重新整合”提交原来的 `POST /ask/{id}/retry`，不新建另一条回答。
- 进度读取失败或还没结束时，“继续查看”仅 GET 原 ID；不会因丢进度而自动再次调用模型。
- 请求有 15 秒截止时间，覆盖响应头及 JSON／HTML 响应体读取。连续 3 次网络／坏响应失败暂停；
  403／404 立即停止；健康轮询最多 300 次或 30 分钟，再由读者继续查看。
- 初次 POST 结果未知时显示问库入口，让读者先查看记录，不自动重提。清空会丢弃迟到响应。
- 保留 Enter 发送、Shift+Enter 换行；输入法组合期间及 keyCode 229 不发送。

这些是浏览器等待边界，不是后端任务超时或取消机制。后端过期、重试领取和迟到工作者保护仍由原问库负责。
