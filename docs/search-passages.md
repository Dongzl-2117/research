# 搜索片段：实现、评测与交接

用户搜索「Costco 商业模式」要的是论述原文：会员费怎样支持商品薄利、周转怎样减少资金占用。
只有公司名，或把别家公司的经营事实放在 Costco 标题下面，不应排成相同相关性。

## 实际链路与能力边界

`/search` → `search_articles` → 别名/词组解析 → 词法与可选向量候选 → 片段排序 → 每篇最多两个上下文窗口。
它原本已有段落打分，并非文章命中后随便取开头；但公司词频、标题上下文和主题被混在一个分数里。
旧页面又围绕最早命中的词截约 88 字，可能只显示公司名、截掉后面的机制。两段摘录还共用第一段的文章链接。

`/ask` 是另一条交互：先检索，配置了站内 LLM 后再扩同义词、分批读资料并整合。
普通 `/search` 不调用付费聊天模型扩词，也不因为打开搜索排导读任务。

没有配置向量服务、没有可用向量或服务失败时，仍只做词法检索。页面会说明降级。
仅凭规则无法保证识别所有未写主题词的隐含论证，也不能可靠判断「本文没有分析某主题」是不是答案。
不要把合成固定向量测试当成真实语义质量验证。

## 本次实现

- 公司词只提供主体依据，主题另算词法与向量分；向量查询去掉公司名，避免相似度主要来自实体名称。
- 主体依据依次考虑当前段、章节、同节上一段及较弱的文章标题；正文明确转谈别家公司时不从标题继承主体。
  沿用公司别名规则和深入/顺带提及强度，不建立 Costco 或行业关键词模板。
- 相邻同节命中合成一个窗口，保留中心块的编号和锚点。每条摘录分别回链，展示必要上下文；全文摘要不再占搜索片段的位置。
- 原文、OCR、译文可共存；仅当译文已有主题证据时，省去同篇只有公司名命中的弱英文摘录。
  不能因为存在任意译文，就删除其他英文或图片文字。
- 所有检索路径拒绝与当前原文 hash 不符的译文，包括残留的旧译文块、标题、上下文和向量。
  旧译文记录仍可供阅读；本次不做正式库清理。
- 选择性吸收 PR73 的检索向量一致性：模型、当前块及标题/章节/正文 hash 校验，请求前后复核，拒绝项本轮跳过。
  未吸收它的部署、迁移启动或身份协议。
- 显式公司范围保留；冲突作者范围取空交集。文章被截断时，即使没有章节标题也把覆盖不足传给各批模型输入及统计。

## 同数据评测

`tools/retrieval_eval/topic_cases.json` 是人工标注的匿名合成原文，不是真实作者言论。
前六题参与开发回归；最后两题由独立子任务在主要排序设计完成后提供，首次运行前未查看查询文本。
之后只做不改变排序语义的性能处理。标签、负例和全部结果都应保留，不能只报告有利的题。

以下关闭向量，在同一 PostgreSQL/zhparser 环境对比 main `6e1fcdb` 与本实现。
最新 main `258507a` 在检索部分没有差异，包含的问库/OCR更新已重放保留。
P@k 分母固定 k，空位算不相关；覆盖按前十窗口中完整出现的标注原文块计算。

显式公司范围违反均为 0。小集合三次查询中位耗时：改前约 2.5–5.8ms，改后约 3.5–8.9ms；不代表生产延迟。
原有 1500 篇/10463 块基线仍需照跑，原 `baseline.json` 不改。

前列结果的具体含义：

- 「开市客的商业模式依赖会员费与商品低毛利，快速周转减少资金占用」属于直接机制证据。
- 「它的商业模式……会员费……续费率」通过同节上文确认主体，和相邻段只展示一个窗口。
- Costco 标题下面的 Walmart 商品经营段被拒绝，不能凭文章标题给它换主体。
- 英文会员费/薄利段在无向量时只能作为弱部分命中；出现在前十不能证明模型理解了中英同义关系。
- 「本文没有分析 Costco 商业模式，只记录一个待研究的问题」仍可能位居前列。
  这是明确保留的困难负例，说明目前不能宣称完整满足语义论述检索验收。

## 复跑与后续

所有破坏性评测只接受显式 `research_eval_*` 库；测试前核对 `current_database()`。

```bash
DATABASE_URL=postgresql://research:research@127.0.0.1:5432/research_search_test \
ALLOW_TEST_DB=1 pytest tests/unit tests/integration
python tools/retrieval_eval/gen_corpus.py --articles 1500 \
  --url postgresql://research:research@127.0.0.1:5432/research_eval_search
EVAL_URL=postgresql://research:research@127.0.0.1:5432/research_eval_search \
  python tools/retrieval_eval/evaluate.py --check tools/retrieval_eval/baseline.json
python tools/retrieval_eval/topic_eval.py \
  --url postgresql://research:research@127.0.0.1:5432/research_eval_topic \
  --check tools/retrieval_eval/topic_baseline.json --out /tmp/topic-results.json
```

真实模型验收尚未完成：本环境无本地权重/runtime，首次读取官方多语言 MiniLM 公共接口被代理 403 拒绝后停止。
没有更换路线、配置凭据或用 stub 代替。mini/生产没有访问。
后续在已有授权且可运行的真实双语向量模型上，用同样样本再测主题召回、归属、负例、跨语言、覆盖和延迟；
向量模型不合适时应调整模型或增加可测的重排层，不能不断堆公司专属词表。

本次无 SQL 迁移、无自动全库向量重算、无合并或部署。运行中的 embedding 回填沿用现有限额。
翻译 worker 重试饥饿、论点缓存等其他审查发现不在本 PR，需要分别的小 PR。
