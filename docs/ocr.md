# 图片里的字（OCR）

截图里的财报表格、聊天记录、标注过的图表，检索和问库原来完全看不到。现在把本地图片交给站内 deepseek-flash 识图（`llm.chat`，多模态 content），识别出的字切成段落块进检索。只有这一种识图；10-30 以前另有一条 RapidOCR 回退，已经删掉（见下面「以前的 RapidOCR 结果」）。

- 按图片内容哈希只识别一次，结果存在 `image_texts`，`engine` 默认 `deepseek-flash-vision`。多篇引用同一张图不重复识别；识别不出字的也记一行，不反复去认。识图失败（无 key 在开工前退出；单张 HTTP 错）记 `engine` 以 `:error` 结尾、正文为空，下次不带 `--redo` 也会重试，不写进脏字。
- 11-07 起识图交回结构（谁说的、是不是截图主人、引用的哪条、哪条被图片边缘截断），后面只排版和拼接，见下面「识图交回结构」。这一节其余几条和「阅读页和模型各看什么」里按 App、按案例写的整理规则，只作用在以前识的图（`image_texts.units` 为空），已经冻结，不再往里加。
- 以前的识图提示词要模型按气泡从上到下转写：绿色气泡写成「方伟：」，其他人写成「截图上的网名：」，看不清网名时才写「网友：」。这些旧结果整理时，输出若已经是「方伟：/网友：/昵称：」，旁路和检索仍再剥界面字，不把 UI 行标成说话人。阅读页不铺这些字。
- 雪球 App 的加群卡（雪球专属交流群、加群交流、股民必入、与高手畅聊热点）、雪球财富陪伴官的邀请、影响力徽章（十年知己、十大影响力用户）、底栏「去基金首页 自选 我的」、风险提示「用户发表的所有文章仅代表个人观点…」，以及「N位达人赞过」「投诉」「屏蔽用户」「收藏」「收起」这类页脚整行删掉，句子里提到的不动。雪球/微博的 `//@` 回复链按时间从早到晚展开时，每一楼的网名照留，壳里拿不到名字才写「网友：」。评论区「只留方伟」的规则没改（`zsxq_comments` 和 poster_role=guest 隐藏读者帖都不动）。
- 识别出的汉字、字母、数字够 20 个的图才切检索块：`article_chunks.lang = 'ocr'`，块号从 20000 起，标题「图片里的字」，锚点是 `img-<哈希前 12 位>`。检索块先走和旁路同一套整理，界面字不进检索。长群聊分几张截时，后一张开头和上一张结尾重叠的整句（去掉标点后 8 个字以上）只进前一张的块，和文章页一样；「同意」这种短回复不算重叠。以前这几句在相邻两块里各一遍，接口「图片里的字」、检索片段和抽观点的输入里都重复。检索和问库走这些块，不另建索引。块只在识图、导入时切：整理规则改了以后，已经切好的块不会自己变，要跑 `research-rebuild-chunks --ocr` 按现在的规则重切（先加 `--dry-run` 看多少篇会变）。它只读 `image_texts`，不识图、不调模型，也不改旁路 `articles.ocr_text`，免得短帖被排去重做摘要和观点；改过的块由夜间 `research-embed` 重算向量。
- 阅读、摘要、观点放宽到 8 个字。空白、水印、几个字的装饰不算。刚过线的拿不准，算有用，不能漏。不按「是不是微信、是不是表格」分：有可读的字就用。
- 公司提及不看图片里的字，免得水印、表情包里的字乱记。这条不变。
- 识别结果另外写在文章旁路 `articles.ocr_text`。微信群聊截图先整理成「方伟：」「网友：」再写入：绿色气泡是作者自己，标成方伟；灰色、带别人昵称的标成网友，不留本名（含「李小红@think」、Kevin）。以前 RapidOCR 认的图，靠右的绿气泡行带侧标记，整理时认成方伟。没有坐标的旧结果里，不带别人昵称的气泡也当绿色本人，不再因为没写「方伟」就标成网友。显示名「方伟-最近在杭州」仍是方伟。句子里的 @方伟 不是说话人。方伟连续说的合成一块，网友每次开口仍分开。跨图重复的句子只留一次。群名、价格（含粘在商品上的「￥19.?」）、小程序及其误识「小小程序」、美团外卖、店名和商品卡、「设为群待办」、「群聊的聊天记录」（单独成行、粘在句尾，或带着日期的标题行）、状态栏时间（含「10:38≥」）这些界面字去掉；状态栏「10:57 :!!! 5GA ■」连着 App 标题的整行去掉，粘在第一句话前面的只去掉状态栏；App 标题单独识成一行（「■知识星球」）的也去掉，句子里提到知识星球的不动。群里的系统提示（「你邀请"某某"加入了群聊 撤销」「"某某"与群里其他人都不是朋友关系，请注意隐私安全」、扫码进群、改群名）整段去掉，里面是群友的昵称；邀请和隐私提醒和上一句话粘成一行的，只切这一段。群名下面置顶的那条消息（「某某：半句..  移除」，带截断点、以「移除」收尾）每张截图都有，整行去掉，不当网友开头，免得下面接着的几行跟着记到网友名下（23860）；正文里说到「移除」的不动。知识星球的引用回复不是这套绿/灰气泡：第一条「方伟看十年」或「方伟看十年作者」账号栏上面的灰字是「网友：」，栏下的回复是「方伟：」，账号栏和下一帖标题去掉；栏上没有正文时仍整段是方伟。表格和贴成长文的图仍是原文。摘要和观点交给模型的正文接上这份整理后的字，和正文一视同仁。有效字少于 8 个的图不进这条旁路。打开文章时按已识别的字重写这一篇的旁路（不重新认图，也不扫全库）。观点和摘要再读这篇时，只要还挂着 `image_texts`，也会按当前规则从原始识别重写，避免库里已经写成「方伟：」的旧旁路把引用回复分不回来。
- 正文不足 400 字时，图片文字和上次抽的时候不一致，摘要会重排；打开这篇文章也会只排这一篇，不扫全库。已经写出判断的长文不会因为后补了一张图就整篇重抽。
- 识图写回 `ocr_hash` 之后（`research-ocr`），短正文会记进 `article_followups`：摘要一篇、方伟星球再加标题一篇。不看标题现在像不像壳——「没有可读文字」「本文正文为空」这类空壳以前不会被 `title_needs_ai` 认出来。同一次命令里最多接着重写 30 篇；剩下的留在队里。摘要队列把入队的、以及短正文哈希对不上的，排在「还没有摘要」的积压前面。标题回写（`--ai-titles`）也先处理入队的。完好的标题（例如「关于携程与Booking」）只出队，不打模型。长文不因为补了一张图就重排。应用启动不跑这一步。
- 观点队列：深入提及照旧。正文不足 400 字、图片里又有字的，一带而过也抽——判断经常在截图里，不能因为深度是一带而过、或内容来自截图就跳过。长文里顺带一提的公司，不会只因为旁边有张图就抽。夜间任务仍按原来的篇数上限，深入提及排在前面；全库重跑不由这次改动自动开始。单篇可以用 `research-views --articles <id>`。公司不在公司表里就没有观点可抽。
- 重复文章（见 [ingest.md](ingest.md)）里的图不认。

## 识图交回结构（11-07 起）

以前识图交回一段自由文字，谁说的话、哪行是界面字，都靠 `wechat_dialogue` 按冒号、App 名和案例一条条猜。新 App、新版式一出来就要再补一条（上面的雪球加群卡、置顶消息、刊头 Logo 都是这么来的），补了还会误伤别的图。看得见图的只有识图模型，这些判断放在识图那一步做完，后面只排版。

- **提示词**（`ocr.py` 的 `VISION_PROMPT`）要一个 JSON：`{"kind": …, "blocks": […]}`。块有三种：消息（`speaker` 照图上的名字抄；`self` 是不是截图的人自己发的，只认聊天界面里靠右的气泡，帖子、评论里标着「作者」「楼主」的是那个帖子的作者，常是别人，写 false；`quote` 引用或回复的那条；`cut` 被图片上下边缘截掉），段落，表格。提示词只写通用的判断：只写内容不写界面，拿不准时想「读者转述这张图时会不会说这句话」；按发言先后排，被回复的那条更早；折行接成一句；看不清写 `?`，不用图里别处的词补；图上没标的数不估。不列哪个 App 有哪些界面字，也不放具体案例。遇到新版式出错，改这几条通用说明，不加规则。
- **存储**：结构存在 `image_texts.units`（迁移 031），`text` 列照样存排好的字，只读 `text` 的地方（阅读页挪图、译制核对）不用改。`researchlib/ocr_units.py` 校验和排版：截图的人自己发的，和显示名是来源作者本人账号的（来源配置的 `author`、`poster_names`，启动时同步进 `sources.poster_names`；判断和评论区「只留作者」同一个 `zsxq_comments.is_owner`），写成「方伟：」，再按来源换成作者名（乘风破浪的写「乘风破浪：」）；看不到名字写「网友：」；其余照图上的名字。作者在截图里用了配置里没有的名字时，写的就是图上的名字，要算作者本人，把这个名字加进那个来源的 `poster_names`。同一个人连着说的并成一段；引用的那条写在回复前面，前面写过就不再写；表格一行一行，格子之间用「 | 」。
- **连着截的几张**按首尾重合拼起来：上一张末尾和下一张开头是同一个人说的同样几条（去掉标点后至少 8 个字），只留一份；上一张最后一条标了 `cut: bottom` 的换成下一张里完整的那条，认错一两个字也认得出；下一张第一条标了 `cut: top`、上一张里已经有完整的，去掉；两头都截了的接成一条。只拼相邻的两张结构化的图，中间隔着旧格式或没字的图就不拼。说话人不同的不合并，只重合一句「好的」不算接着截。
- **结构化的图不再过旧规则**：旁路 `articles.ocr_text`、检索块、摘要和观点的输入、提示里那句说话人说明（不再因为冒号前的名字少见就写「尚未确认说话人边界」）、检索引用条，都按排好的字走，不过 `wechat_dialogue`、`vision_polish`。同一篇里新旧两种图都有时，旧的那几张照旧整理，前后顺序不变。
- **模型没按格式交**（回了自由文字）：照旧存字，`units` 为空，按旧规则整理，这次的钱不白花。**回了 JSON 却读不出来**（多半是输出被截断）：同一张图再要一次，还不行记 `engine` 以 `:invalid` 结尾、正文为空，夜里不自动重试（重试又要花钱），要重认用 `--redo --article` 点名。
- **旧规则冻结**：`wechat_dialogue`、`vision_polish`、`normalize_vision_text` 只给 `units` 为空的旧识别用，不再往里加规则。库里的旧识别和旁路一字不改，不会因为这次改动排去重做摘要和观点。旧图（约 1.1 万张）要不要按新格式重认、用什么思考强度，由 Zhilin 定（11-08 按 6 张实测算过账，见下面「全库重认」）；旧图都重认完以后，再删这几套旧规则。
- **还按旧规则过一遍的地方**：星球空壳标题的取材（`zsxq_display_title` 的 `ocr`）仍把旁路过一遍 `present_stored_ocr`，只影响列表上补出来的标题，对结构化的字几乎是原样。

**用量**：识图请求带 `stream_options.include_usage`，接口报的 token 存在 `image_texts.usage`（`prompt` 输入、`completion` 输出、其中思考的 `reasoning`；读不出来再要的那次也算上）。`research-ocr` 结束时多打两行：按结构交回、交回自由文字、读不出来各几张；用量合计和每张平均。接口或转发不认这个参数（4xx）时去掉再发一次；去掉以后成了，这一次命令后面的请求都不再带，也就没有用量，报告写「接口这次没报用量，花费看 DeepSeek 账单」。跑过一晚以后按库里的记录算：

```bash
docker compose exec -T db psql -U research -d research -c "
SELECT count(*) AS images,
       round(avg((usage->>'prompt')::int)) AS avg_prompt,
       round(avg((usage->>'completion')::int)) AS avg_completion,
       round(avg((usage->>'reasoning')::int)) AS avg_reasoning,
       count(*) FILTER (WHERE units IS NOT NULL) AS structured
FROM image_texts WHERE usage IS NOT NULL"
docker compose exec -T db psql -U research -d research -c "
SELECT engine, count(*) FROM image_texts WHERE created_at > now() - interval '2 days' GROUP BY 1 ORDER BY 2 DESC"
```

第二条看最近两天各种结果的张数：`:invalid` 多了说明输出常被截断或格式不对，先看日志里「识图结构读不出来」那几张，再改提示词的通用说明。

## 阅读页和模型各看什么

文章页、中英对照和飞书目录右侧是阅读：正文里的图保持原来的 `<img>`（知识星球、公众号导出里图在哪，页面上还在哪）。不把 `image_texts` 换成对话、表格或「原图 N」链接，也不在图上叠字。点图仍可放大；检索「看这张图」的锚点 `img-<哈希前 12 位>` 在这张图上。栏宽约 680px（`--reading-column`），图不超过这一栏，竖图再限高。

只有方伟公众号（kind 是 `wechat_mp`）以前的正文会挪图：11 月 7 日以前的抓取取的是极致了的正文，按段估图的位置（第 N 张图放在第 N 段后面），图会整组堆在开头的引文里。阅读页按识图里的字把图挪到对得上的那一段前面，字不进正文（#244）。11 月 7 日起方伟公众号和孤独进化体一样从公众号原文页取正文，归档头写「- 图片位置：原文页」（`raw_meta.images = "page"`），图就在原位，不挪；以前入库的那些，抓取脚本每次按原文页挪回原位一批（`research-place-wechat-images`，见 [ingest.md](ingest.md)「方伟公众号老文章的图」），挪好的同样记 `images = "page"`，挪不了的才照旧按识图挪；别的来源图本来就在原文的位置，也不挪（`render.images_placed_by_estimate`）。以前所有来源都挪：飞书一张利润表截图跟在「下图是年报里的合并利润表：」后面，因为和下一节的一段同有「归属于母公司股东的净利润」，被挪到了那一段前面。

识图文字只给模型：摘要、观点、论点、问这篇、检索块（`article_chunks.lang = ocr`）和旁路 `articles.ocr_text`。这些路径仍查 `image_texts`，用和旁路同一套整理（`wechat_dialogue` / `present_ocr_pieces`），正文后面接上「【图片里的字】」。不改库、不重跑识图，阅读页也不会因此少图。下面这些整理规则作用在模型输入和检索，不作用在阅读 HTML。

## 站内识图

`app` 容器就能跑。`research-ocr` 调用站内 `deepseek-flash`（和问库、摘要同一模型）。送识图前，超过约 210KB 的图用 Pillow 把长边缩到 1920 以内、转成 JPEG，压到 280KB 以内（`ocr.py` 的 `MAX_VISION_SEND_BYTES`、`VISION_MAX_SIDE`），避免 DeepSeek 转发链路掐断大 data-url；瞬时断连会重试最多 3 次。识图请求的 max_tokens 固定 65536（覆盖站点默认下限；8k/16k/32k 在 thinking 下会把正文挤空，text 侧另有空正文自动加额度重试），避免流式思考把容器 OOM。定点重认：

```bash
docker compose exec -T app research-ocr --redo --limit 50 \
  --article 24002 --article 24007
```

单张失败记 `:error` 和空正文，下次会重试。没配 `DEEPSEEK_API_KEY` 时开工前就退出，退出码 2。`--engine vision` 还认，是给以前写好的命令（`scripts/nightly.sh`）留的，不写也一样。每张图都要调一次模型，要花钱。

**全库重认**（不点名文章的 `--redo`）：每行记着按第几版识图说明认的（`image_texts.prompt_version`；现在是 `ocr.VISION_PROMPT_VERSION` = 1，迁移 032 把识图交回结构以后认的行记成 1，以前的留空）。全库重认只认版本比现在旧的图，按文章从新到旧；停了再开从没认完的接着认，认过的不再付一次钱。以前它每次都从最新的图从头认，11-08 线上重开一轮 2 万张的重认，停下再开就会把刚认过的再认一遍。点名的 `--redo --article` 照旧全部重认。`--redo --limit 0` 不认图，只打出还剩多少张、其中以前认出过字的多少张。改了 `VISION_PROMPT`、要让旧图按新说明重认时，把 `VISION_PROMPT_VERSION` 加一；措辞小改不值得花钱重认的不加。

11-08 按线上 6 张实测（`reasoning_effort=max`，都按结构交回）：每张输入约 1.9k token、输出约 1.16 万（97% 是思考），80 到 90 秒，夜间价约 0.007 美元，工作日 9 到 12 点、14 到 18 点（北京时间）翻倍。剩下约 1.1 万张旧图全认约 80 美元、一张一张认要连续跑 11 天左右；短帖（正文不到 `SHORT_BODY_CHARS`）的图片文字一变，摘要和观点会跟着重做，而且排在新文章前面。要不要认、用什么思考强度，由 Zhilin 定。

跑的时候自动上线先不重建（`scripts/deploy.sh` 看 `docker compose top app` 里有没有 `research-ocr`）。它在等的提交 CI 过了，就写 `data/status/.deploy-waiting`：不点名文章的识图认完手上这张就停，打印「自动上线在等」，排上的摘要重写留在队里，下一轮（10 分钟内）上线；上线后再开，从没认完的接着认。点名的 `--article` 认完才停。夜间任务里的那一步不用让路，自动上线等的是整个夜间任务。

## 每晚补一批

夜间任务（[backup.md](backup.md)）默认不跑识图。要每晚补新图：

```bash
NIGHTLY_OCR=1 BACKUP_DIR=… scripts/install-launchd.sh
```

之后每晚补完外链图片，就在 `app` 容器里跑 `research-ocr --engine vision`（`OCR_LIMIT`，默认 400 张，和其他步骤共用 `MINUTES` 的时间上限），排在语义向量、观点、摘要前面：当天的截图帖第一遍就带着图里的字抽观点、写摘要，图片文字块当晚就算向量。失败了和其他步骤一样记进夜间任务的结果。只挂在知识星球读者帖、「图片」评论壳、停用来源下的图不排队（网站上不展示，认了白花钱）；`--article` 点名的照认，读者帖改回星主帖以后，下一晚自然会排上。

`app` 容器没在跑时，这一步会先 `docker compose up -d app` 再执行，避免 `service app is not running` 直接失败。导入命令本身不识图，新导入的带图文章（方伟星球、方伟公众号，以及其他来源）靠这一步识图；没设 `NIGHTLY_OCR=1` 时要手动跑 `research-ocr`。

第一次可以先用 `research-ocr --article` 定点重认抽验锚点，不要无差别全库 vision。以后每晚只剩新导入的图。

短正文的 `ocr_hash` 若在这一步变了，命令结束前会用同一套站内 deepseek-flash 重写最多 30 篇摘要，方伟星球的空壳标题也一起重写；不是全库，长文不重排。没写完的留在 `article_followups`，下次摘要优先拿。
