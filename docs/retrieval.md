# 检索怎么找原文

检索页（`/search`）、问库（`/ask`）和 JSON 接口（`/api/v1/search`、MCP 的 `search_library`）用的是同一套召回和打分，代码在 `src/researchlib/retrieval.py`。目标是两件事：针对问的问题，找出相关性最高的原文段落；库变到几十万段以后，仍然准、全、快。

## 以前的问题

- 检索页用 `websearch_to_tsquery`。不带空格的中文整句会被当成一个连续短语，「腾讯广告加载率」搜不到写着「腾讯的广告加载率」的文章，「苹果定价权」搜不到「苹果在高端手机上的定价权」。只有手动加空格才命中。
- 问库把问题的所有词用「或」连起来，按 `ts_rank_cd` 排序。这个排序不看词有多常见，「公司」「数据」「核心」这类泛词和真正的检索词一样重。公司页「问 AI：库里怎么看 X」的预设问题里没有公司名，前 14 段几乎全被泛词段落占满，常常根本没提这家公司。
- 交给模型的材料最多 14 段、约 9000 字，问「按时间梳理」也只有这么多。

## 现在怎么做

### 1. 读懂问题

- 公司用别名自动机认（和提及统计同一套别名），不靠分词。zhparser 会把「看拼多多」切成「看拼 / 拼 / 多多」，靠分词认公司会出错。
- 作者按名字认，认出来就收窄到他的来源。
- 引号里的是必须原样出现的短语，减号开头的是排除词，`or` 把前后两段并成「任一」。
- 剩下的文字交给 zhparser 切词，按词性去掉代词、助词、连词、介词（怎么、哪些、的、和、在），再去掉问句套话（看法、观点、讨论、作者、梳理……）。`multi_short` 补出来的半个词（「护城河」后面的「护城」）只留长的。
- 每个词自成一组，组与组之间是「且」。

### 2. 每个词有多常见

每个词在全库段落块里出现在多少块（df），按 BM25 的公式算 IDF。计数封顶在库的四分之一，超过的已经很常见，精确值不影响排序。结果缓存十分钟。

只有足够少见的词（出现在 6% 以内的块，最多六万块）拿来召回；很常见的词只参与打分。所以库再大，召回也只碰少数段落。

### 3. 召回

几路合并，各路先只取（文章、块号），合并去重后一次取回正文：

1. 全部词组都命中的段落（GIN 索引求交集）。
2. 问到了公司又有别的词：只在提到这家公司的文章里找含这些词的段落。
3. 标题命中的文章取第一块。段落块不含标题，「标题写了、正文没写」的文章不能漏。
4. 任一少见词命中。前几路已经够多就不再撒网。
5. 只问一家公司、没有别的词时（公司页预设）：这家公司被深入提及的文章，按年份分层，每年取一批，深入的优先。
6. 什么检索词都没有时（作者页预设、「汇总这一天」）：范围内各篇的开头两块，新的在前，谈到具体公司的优先。

每一路先在索引命中里封顶取两万块再排名，常见词在大库里也不会拖慢。

### 4. 打分

- BM25：词频按原文逐字数（中文按字面，英文按词边界），文档长度按块长归一。公司按别名数，权重是普通词的 1.5 倍。
- 覆盖率：问题里的词组命中得越全分越高（乘以 0.1 + 0.9 × 覆盖率²）。只命中一个词、但把它重复很多遍的段落排不上去。
- 标题写到的词算进这篇每一段的上下文，但只算半个覆盖。
- 相邻两个词在原文里也连着出现（「渠道」「库存」→「渠道库存」）加分。
- 段落谈到问的公司、所在文章是标题或全文深入谈它的，加分；只在一带而过的文章里出现的，减分。
- 问「最近」时按发布时间加权；问到某一年（「2024 年」）时偏向那一年。

### 5. 挑选

- 低于榜首 12% 的不要；全词命中的段落已经不少时，只命中一半以下的也不要，免得用噪音填满名额。
- 每篇封顶 2～3 段。
- 梳理类问题（梳理、变化、历年……）和只问公司的，按年份轮流取；「哪些作者」类按作者轮流取。问「最近」时不摊年份。

份量按用途：问库页马上列出的「相关原文」40 段；一次交给模型 80 段、约 6.4 万字；资料多时分批读，最多 240 段、18 万字。

### 6. 交给模型整合

问库提交后先列出相关原文，模型在后台整合，回答页每几秒问一次状态，写完自己刷新。不在一个请求里等模型：站点在 Cloudflare 后面，单个请求大约 100 秒就会被断开（524）。

后台整合的步骤：

1. 让模型给问题里的检索词补同义说法（「护城河」→「壁垒」「竞争优势」），只输出 JSON。同义词并进原词所在的组，权重 0.7；模型补充的新词单独成组，只加分、不计覆盖率。
2. 用扩充后的词再检索一遍，这次取 240 段以内。
3. 一次读得完（6.4 万字以内）就一次作答；读不完就按 4.8 万字一批分批摘录要点（每条带原始编号），三批并行，最后汇总成回答。摘录用 `reasoning_effort=low`，汇总用配置的 `high`。
4. 写回回答和出处。进程重启时没写完的标成中断，回答页可以「重新整合」。

## 评测

`tools/retrieval_eval/` 里有一份可控的评测语料生成器和评测脚本。语料按作者、年份（2019～2026）、公司、主题生成，每段带真值；正文里混了大量「公司、数据、核心、时间」这类套话，主题用同义说法（护城河 / 壁垒 / 竞争优势 / 门槛），还有「比如腾讯」这种顺带提及。

6000 篇、41,929 个段落块上，改前改后：

| 用例 | 问库准确率 改前 → 改后 | 年份覆盖 改前 → 改后 |
| --- | --- | --- |
| 方伟最近怎么看拼多多的护城河 | 43% → 95% | 2/8 → 8/8 |
| 腾讯广告加载率 | 100% → 100% | 5/8 → 8/8 |
| 茅台批价和渠道库存 | 50% → 100% | 4/8 → 8/8 |
| 苹果的定价权 | 54% → 100% | 4/8 → 8/8 |
| 公司页「库里怎么看腾讯」 | 8% → 100% | 1/8 → 8/8 |
| 作者页「近期核心判断」 | 46% → 100% | — |
| 12 个用例平均 | 68% → 100% | |

改前每题最多 14 段，召回率普遍在 6% 以下；改后交给模型 80 段，资料多时 240 段。

检索页（前 20 篇的准确率）：改前 7 个关键词查询里 5 个一篇都搜不到（「腾讯广告加载率」相关文章 203 篇，搜到 0 篇）；改后 7 个都能搜到，前 20 篇全部相关。

模型补同义词的效果（用固定的同义词模拟模型输出，240 段）：「方伟怎么看拼多多的护城河」召回率 66% → 98.5%；「苹果的定价权」75% → 83%，准确率 90% → 100%。

耗时：把语料复制成 7 倍（29 万个段落块），问库检索每题 0.1～0.6 秒（改前遇到常见词要 2～3 秒），检索页 0.2～1 秒。以上是纯 Python 版 psycopg 测的，正式环境用的二进制版取数更快。

重跑：

```bash
createdb research_eval
psql research_eval -c "CREATE EXTENSION zhparser"
python3 tools/retrieval_eval/gen_corpus.py --articles 6000
python3 tools/retrieval_eval/evaluate.py
```

生成器只写名字以 `research_eval` 开头的库。改了检索之后跑一遍，看准确率和耗时有没有退步。
